# Non-Functional Requirements (NFR)

This document is the source of truth for the non-functional behaviour of the
Temp Master dashboard. The thresholds in `switchbot-dashboard/load-tests/*.js`
are derived from the SLO table below — change the table and the tests together.

## 1. Performance SLOs

Measured at the backend HTTP boundary, warm cache, seeded with 10 devices ×
500 readings.

| Endpoint | p95 | p99 | Error rate |
|---|---|---|---|
| `GET /api/status` | 100 ms | 250 ms | < 0.1 % |
| `GET /api/meters` | 200 ms | 500 ms | < 0.1 % |
| `GET /api/meters/{id}/history` | 300 ms | 800 ms | < 0.1 % |
| `GET /api/latency-stats` | 500 ms | 1000 ms | < 0.1 % |

## 2. Expected traffic

| Property | Value |
|---|---|
| Steady-state | 50 req/s |
| Peak (burst) | 400 req/s for up to 1 min |
| Concurrent dashboard users | 100 |
| Traffic mix | 45 % `meters`, 45 % `history`, 10 % `latency-stats` |

## 3. Data volume assumptions

| Property | Value |
|---|---|
| Devices | 10–50 meters |
| Readings per device | 1 per minute, retained 1 year (~525 k rows/device) |
| Row size | ~64 bytes |
| Distribution | Uniform over time; stale meters (> 7 days idle) excluded from charts |

Load-test data is **synthetic** — generated by `load-tests/seed.js` via
`POST /api/import`. No production or personal data is used.

## 4. Reliability / capacity

- Availability target: 99.5 % monthly.
- The SwitchBot upstream is rate-limited; the backend must keep serving cached
  data (`/api/meters`) while `is_rate_limited` is true.
- Graceful degradation under overload is acceptable (elevated latency); 5xx
  responses are not.

## 5. Security & supply chain

- `pip-audit` / `npm audit` clean of high severity findings.
- No credentials in the repo; `SWITCHBOT_TOKEN` / `SWITCHBOT_SECRET` come from
  the environment.

## 6. Test rules of engagement

- Load tests run against **staging or a local instance only**, never production.
- `POST /api/meters/refresh` is excluded from load scenarios: it calls the
  external SwitchBot API and would trigger rate limiting.
- `POST /api/import` is used for seeding only, not as a load target.

## 7. How results are judged

A run passes when every k6 threshold passes (k6 exits non-zero on breach).
The JSON summary is uploaded as a CI artifact for trend comparison.
